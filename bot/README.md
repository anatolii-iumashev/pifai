# ПиФ бот — локальная разработка и тестирование

## Подготовка

1. Перейди в папку `bot/`:
   ```bash
   cd /Users/evgrezanov/projects/wpcraft/pif/bot
   ```

2. Установи зависимости:
   ```bash
   npm install
   ```

3. Создай файл `.dev.vars` с секретами:
   ```env
   TELEGRAM_BOT_TOKEN=your_telegram_token
   GROQ_API_KEY=your_groq_api_key
   GROQ_MODEL=llama-3.3-70b-versatile
   KNOWLEDGE_VERSION=1.0.0
   ```

---

## Запуск в локальном режиме

Для разработки используй:
```bash
npm run dev
```
Это запустит локальный Hono-сервер на `http://127.0.0.1:8787`.

Если хочешь запустить через Cloudflare Workers эмулятор:
```bash
npm run preview
```

---

## Проверка работы

### 1. Проверить health

Открой в браузере или через curl:
```bash
curl http://127.0.0.1:8787/health
```

Ожидаемый ответ:
```json
{"status":"ok","hasSecrets":true,"knowledgeVersion":"1.0.0"}
```

### 2. Проверить веб-интерфейс

Открой:
```bash
http://127.0.0.1:8787/ui
```

Веб-страница должна загрузиться и показать чат.

### 3. Проверить API `/api/chat`

Выполни:
```bash
curl -X POST http://127.0.0.1:8787/api/chat \
  -H "Content-Type: application/json" \
  -d '{"userId":"web-test","message":"Привет, как ты?"}'
```

Ожидаемый ответ:
```json
{"answer":"..."}
```

Если приходит `answer`, веб-канал работает.

### 4. Проверить Telegram webhook

- Убедись, что бот развернут или доступен через ngrok/Cloudflare.
- Установи webhook на адрес `https://.../webhook`.
- Отправь боту сообщение в Telegram.

Если бот отвечает, Telegram-канал работает.

## Тестовый сценарий

### Сценарий 1: базовое подключение

1. Запустить `npm run dev`
2. `curl /health` → статус ok
3. Открыть `/ui` → загрузка страницы
4. Отправить сообщение через веб-интерфейс → получить ответ
5. Отправить `POST /api/chat` вручную → получить JSON с полем `answer`

### Сценарий 2: проверка общей логики

1. Отправить в веб `Я чувствую тревогу перед встречей`
2. Убедиться, что бот отвечает эмпатично и в духе ННО
3. Отправить повторный запрос из того же `userId` → проверить, что история используется
4. Сравнить с Telegram: отправить тот же текст в Telegram → ответ должен быть аналогичного стиля

### Сценарий 3: отказоустойчивость

1. Отключить переменную `GROQ_API_KEY` или дать неверный токен
2. Запрос `POST /api/chat` → получить понятную ошибку
3. Запрос `GET /health` → `hasSecrets: false`

## Дополнительно

- Для production используй `npm run deploy`
- Веб-страница генерирует `userId` и сохраняет его в `localStorage`
- История сессий хранится в Cloudflare KV на стороне Worker
