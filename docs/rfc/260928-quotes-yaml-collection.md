# RFC: Цитаты как YAML content collection

## Вводные

**S.** Раздел «4. Цитаты великих людей» — это 10 тематических Markdown-страниц в `src/content/docs/quotes/`. Цитаты в них захардкожены блоками `## Автор` → `> «цитата»` → «Контекст» → «Для размышления»: всего ~125 цитат от ~20 авторов.
**C.** Цитата — это не текст, а запись данных. Сейчас одна и та же цитата копируется на несколько страниц (Эпиктет о свободе, Гумбольдт о судьбе). Имя автора пишется по-разному («Паскаль» / «Блез Паскаль», «Кант» / «Иммануил Кант»). Выбрать цитаты по автору или теме нельзя, структуру никто не проверяет.
**Q.** Как хранить цитаты, чтобы у каждой был один источник правды, проверяемая структура и выборка по автору и теме, и при этом не приходилось придумывать имя файла для каждой цитаты?
**A.** Переносим цитаты в Astro [content collection](https://docs.astro.build/en/guides/content-collections/) `quoteAuthors`. **Один автор — один YAML-файл** (`src/content/quotes/leo-tolstoy.yaml`): в нём метаданные автора и массив `quotes`. Файлы загружает `glob()`, структуру проверяет Zod-схема. Тематические страницы становятся `.mdx` и выводят цитаты компонентом `<QuoteList topic="…" />`.

## Назначение и цели

1. **Один источник правды.** Цитата хранится ровно в одном месте — в файле своего автора. На тематической странице она появляется через привязку к теме, а не копированием.
2. **Проверяемая структура.** Ошибка в поле или неизвестная тема роняют `astro check` / `astro build`, а не остаются незамеченными.
3. **Выборка по автору и теме.** Цитаты доступны через хелпер поверх `getCollection('quoteAuthors')`. Это нужно для страниц, для бота («цитата дня», «цитата по теме») и для будущих страниц авторов.
4. **Дешёвый ingest.** Чтобы добавить цитату, агент дописывает элемент в массив файла автора. Имя файла для цитаты придумывать не нужно, файл автора создаётся один раз.

Почему сейчас: раздел маленький (~125 записей), миграция укладывается в одну сессию. Дальнейший ingest цитат (Юнг, Франкл, Розенберг уже упоминаются в `index.md`) сразу пойдёт в новом формате, иначе ручная миграция будет только расти.

## Составляющие и особенности

Разбиение по слоям — от данных к представлению и процессу: **хранилище и схема → миграция контента → рендеринг → ссылки и навигация → правила агентов**.

### 1. Хранилище и схема

**Структура каталогов.** Данные лежат вне коллекции `docs`, чтобы `docsLoader` Starlight не смешивал их со страницами:

```
src/content/quotes/
├── leo-tolstoy.yaml        # автор + все его цитаты
├── epictetus.yaml
├── marcus-aurelius.yaml
├── talmud.yaml
└── ...
```

**Конвенции именования:**
- Имя файла — id автора: транслит латиницей, kebab-case. Для людей — «имя-фамилия» (`leo-tolstoy`, `marcus-aurelius`, `blaise-pascal`, `immanuel-kant`). Для текстов и традиций — короткое имя (`talmud`, `gospel`, `buddhist-wisdom`, `brahmin-wisdom`, `chinese-wisdom`).
- Расширение только `.yaml`. Вложенных папок нет.
- Цитата не получает собственного имени. Её id — `<author>/<n>`, где `n` — порядковый номер в массиве, начиная с 1. Номер вычисляется хелпером, в YAML его не пишут.
- Новые цитаты **дописываются в конец массива**, чтобы id существующих не сдвигались.

**Коллекция** в `src/content.config.ts` (рядом с существующей `docs`):

```ts
import { glob } from 'astro/loaders';
import { z } from 'astro/zod';
import { QUOTE_TOPICS } from './lib/quote-topics';

const quote = z.object({
  text: z.string().min(1),
  topics: z.array(z.enum(QUOTE_TOPICS)).min(1),
  context: z.string().optional(),                    // «Контекст:»
  reflection: z.string().optional(),                 // «Для размышления:»
  source: z.object({
    work: z.string().optional(),                     // «Евангелие от Матфея», «Мысли»
    via: z.string().optional(),                      // «Л. Толстой, „Круг чтения“ (1906)»
    url: z.string().url().optional(),
  }).optional(),
});

quoteAuthors: defineCollection({
  loader: glob({ base: './src/content/quotes', pattern: '*.yaml' }),  // id = имя файла
  schema: z.object({
    name: z.string(),                                // «Лев Толстой»
    fullName: z.string().optional(),                 // «Лев Николаевич Толстой»
    years: z.string().optional(),                    // «1828–1910»
    kind: z.enum(['person', 'scripture', 'tradition']),
    wikiPage: z.string().optional(),                 // 'authors/frankl/index' — связь с разделом автора в wiki
    quotes: z.array(quote).min(1),
  }),
}),
```

Автор задаётся самим файлом, поэтому ситуация «цитата без автора» невозможна по построению.

**Справочник тем** `src/lib/quote-topics.ts` — единственный список тем. Slug совпадает с именем тематической страницы:

```ts
export const QUOTE_TOPICS = [
  'self-knowledge', 'memento-mori', 'freedom-slavery', 'faith-soul-god',
  'good-deeds-service', 'fate-acceptance', 'thoughts-reality',
  'wisdom-knowledge', 'hatred-anger-forgiveness', 'childhood-innocence',
] as const;
export type QuoteTopic = typeof QUOTE_TOPICS[number];
```

Новая тема = slug в массиве + страница `quotes/<slug>.mdx`.

**Пример** — `src/content/quotes/leo-tolstoy.yaml`:

```yaml
name: Лев Толстой
fullName: Лев Николаевич Толстой
years: 1828–1910
kind: person

quotes:
  - text: >-
      Страх смерти происходит от того, что люди принимают за жизнь одну
      маленькую, ложным представлением ограниченную часть её.
    topics: [memento-mori]
    context: >-
      Страх смерти уменьшается, когда понимаешь жизнь шире — как духовное,
      вечное явление.
    reflection: Что для вас «жизнь»? Только физическое существование или что-то большее?
    source:
      via: Л. Толстой, «Путь жизни» (1910)

  - text: >-
      Жизнь — благо. Этот мир не шутка, не юдоль испытания и перехода
      в мир лучший, вечный…
    topics: [memento-mori, good-deeds-service]
    reflection: Как вы можете сделать мир прекраснее и радостнее сегодня?
```

### 2. Миграция контента

Все цитаты из 10 тематических страниц переезжают в файлы авторов. Правила:

- **Граница цитаты.** Цитата — это блок `> «…»` внутри секции `## <Автор>` вместе со следующими за ним «Контекст» и «Для размышления». Эпиграфы в начале страницы и финальные цитаты `> «…» — Автор` тоже становятся записями, если такого текста ещё нет. Текст в упражнениях, таблицах и блоках кода цитатой не считается.
- **Дедупликация.** Если у одного автора после нормализации кавычек и пробелов текст совпадает, остаётся один элемент массива, а в его `topics` перечисляются все темы. Когда «Контекст» и «Для размышления» в копиях расходятся, берётся вариант с первой по алфавиту темы. Это осознанная потеря, см. «Открытые вопросы».
- **Порядок в массиве.** Сначала по теме в алфавитном порядке slug, внутри темы — в порядке появления на исходной странице. Порядок фиксируется один раз при миграции, дальше записи только дописываются.
- **Нормализация авторов** (таблица соответствия):

  | Заголовок в .md | Файл |
  |---|---|
  | Лев Толстой | `leo-tolstoy.yaml` |
  | Эпиктет, Эпиктет (о Диогене) | `epictetus.yaml` (для «о Диогене» — `source.work: "о Диогене"`) |
  | Марк Аврелий | `marcus-aurelius.yaml` |
  | Паскаль, Блез Паскаль | `blaise-pascal.yaml` |
  | Кант, Иммануил Кант | `immanuel-kant.yaml` |
  | Евангелие от Матфея / от Иоанна | `gospel.yaml` (`source.work` — конкретное Евангелие) |
  | Талмуд | `talmud.yaml` |
  | Будда | `buddha.yaml` |
  | Буддийская мудрость | `buddhist-wisdom.yaml` |
  | Браминская мудрость | `brahmin-wisdom.yaml` |
  | Китайская мудрость | `chinese-wisdom.yaml` |
  | Лао-цзы, Конфуций, Сократ | `lao-tzu.yaml`, `confucius.yaml`, `socrates.yaml` |
  | Джон Рёскин, Гумбольдт, Вольтер | `john-ruskin.yaml`, `wilhelm-humboldt.yaml`, `voltaire.yaml` |
  | Эмерсон, Руссо, Чокке | `ralph-waldo-emerson.yaml`, `jean-jacques-rousseau.yaml`, `heinrich-zschokke.yaml` |
  | «Грамм собственной жизни» (`wisdom-knowledge.md`) | автор не указан (см. «Открытые вопросы»). До решения — `folk-wisdom.yaml` с `kind: tradition`, `name: "Народная мудрость"` |

- **Попутные правки текста.** Опечатка «Для размахления» исправляется на «Для размышления» (3 вхождения). Сами тексты цитат не редактируются.
- **Способ.** Миграцию выполняет агент. Для сверки количества используется одноразовый скрипт в scratchpad, в репозиторий он не коммитится. Число записей до и после миграции (с учётом дедупликации) фиксируется в `log.md`.

### 3. Рендеринг

- **Хелперы** `src/lib/quotes.ts`:
  - `getQuotes({ topic?, author? })` читает `getCollection('quoteAuthors')` и разворачивает массивы в плоский список `{ id: '<author>/<n>', author, ...quote }`, где `author` — запись автора без `quotes`. Затем фильтрует по теме и/или автору.
  - Сортировка: по `author.name`, затем по `n`.
- **Компонент** `src/components/quotes/QuoteList.astro` с пропсами `topic?: QuoteTopic` и `author?: string`. Разметка повторяет текущую, чтобы внешне ничего не изменилось:
  - `<h2>` с именем автора — одна секция на цитату, как сейчас;
  - `<blockquote>` с текстом в «ёлочках»;
  - абзацы **Контекст:** и **Для размышления:**, если эти поля есть;
  - строка источника (`source.work` / `source.via`, со ссылкой при наличии `url`);
  - `<hr>` между цитатами.

  Заголовки `<h2>` попадают в оглавление страницы Starlight так же, как сейчас.
- **Тематические страницы.** 10 файлов `quotes/<topic>.md` переименовываются в `quotes/<topic>.mdx`. Остаются как текст MDX: frontmatter, вступление, эпиграф, «Практика», «Ключевые идеи раздела», «Связанные темы» и «Материалы и источники». Блоки цитат заменяются одной строкой `<QuoteList topic="<topic>" />`. URL страниц не меняются.
- **Индекс раздела** `quotes/index.md` остаётся `.md`. «~115 цитат» и «~20 авторов» заменяются фактическими числами после миграции. Динамический счётчик в рамки RFC не входит.
- **Поддержка `.mdx` в remark-плагине.** В `src/remark-strip-md-links.mjs` та же логика (снять расширение, скорректировать глубину) распространяется на ссылки на `.mdx` и на исходники `.mdx`. Плагин подключён через `markdown.remarkPlugins`, и MDX-интеграция Starlight по умолчанию наследует его. Это нужно проверить на этапе delivery.

### 4. Ссылки и навигация

- Все относительные ссылки на 10 переименованных страниц (`./memento-mori.md` и т. п.) внутри `src/content/docs/` меняются на `.mdx`.
- **Исправляются уже битые ссылки** (находка discovery):
  - `src/content/docs/index.md` (строки 31–35) и `README.md` («Оглавление») ссылаются на несуществующие `quotes/tolstoy.md`, `jung.md`, `frankl.md`, `rosenberg.md`, `others.md`. Их заменяют ссылки на 10 реальных тематических страниц.
  - В `quotes/index.md` ссылки `../techniques/` и `../problems/` заменяются на `../practices/index.md` и `../use-cases/index.md`.
- `index.md` и `README.md` («Оглавление») синхронизируются по правилу `AGENTS.md`.
- В `src/content/docs/log.md` добавляется запись `## [YYYY-MM-DD] update | Цитаты → YAML content collection` с числом цитат и авторов.
- Боковое меню не меняется: `autogenerate: { directory: "quotes" }` видит `.mdx`, а YAML лежит вне `docs` и в меню не попадает.

### 5. Правила агентов

- **`AGENTS.md`:**
  - в дерево «Wiki Structure» добавляется `src/content/quotes/<author>.yaml`;
  - в «Ingest» → «Вдохновляющие цитаты» добавляется правило: цитату дописывают в конец `quotes` в файле автора. Если файла ещё нет, его создают. Если цитата уже есть, дописывают тему в её `topics`. На страницу текст цитаты не пишут;
  - в «General Rules» правило «всегда `.md`» уточняется до «всегда с расширением исходного файла (`.md` / `.mdx`)».
- **`.agents/skills/wiki-ingest`:** шаг для цитат:
  - найти файл автора по таблице нормализации или по `name`;
  - проверить, нет ли уже такого текста;
  - дописать в конец массива;
  - брать `topics` только из `QUOTE_TOPICS`.
- **`.agents/skills/wiki-lint`:** новые проверки:
  - один и тот же автор в двух файлах (совпадает `name` или `fullName`);
  - дубли текста внутри файла и между файлами;
  - тема из `QUOTE_TOPICS`, для которой нет страницы `quotes/<topic>.mdx`.

- [ ] Цитата с несколькими `topics` видна на каждой из соответствующих страниц.
- [ ] `getQuotes()` возвращает id вида `leo-tolstoy/1`. Если дописать цитату в конец массива, id существующих не меняются.

- [ ] Во всём `src/content/docs/` и `README.md` нет ссылок на `quotes/*.md`, кроме `quotes/index.md`, и нет ссылок на `quotes/tolstoy.md`, `jung.md`, `frankl.md`, `rosenberg.md`, `others.md`.
- [ ] Список цитат в `index.md` и «Оглавление» в `README.md` перечисляют 10 тематических страниц и совпадают между собой.

- [ ] `wiki-ingest` и `wiki-lint` содержат шаги и проверки из п. 5.

## Дорожная карта

1. **Хранилище и схема.** `quote-topics.ts`, коллекция в `content.config.ts`, один пробный файл автора. Проверка: `npm run check`.
2. **Рендеринг.** `quotes.ts`, `QuoteList.astro`, поддержка `.mdx` в remark-плагине. Проверяется на одной странице (`memento-mori`): `.mdx` с компонентом дают прежний вид и рабочие ссылки. Это главный технический риск, поэтому шаг идёт до массовой миграции.
3. **Миграция контента.** Остальные цитаты → файлы авторов, 9 страниц → `.mdx`, дедупликация, сверка количества.
4. **Ссылки и навигация.** `.md` → `.mdx` в ссылках, исправление битых ссылок, `index.md`, `README.md`, `log.md`. Проверка: `npm run build`.
5. **Правила агентов.** `AGENTS.md`, `wiki-ingest`, `wiki-lint`.

Шаги 1 → 2 → 3 → 4 выполняются строго последовательно. Шаг 5 можно делать параллельно с 3–4.

## Итого и рекомендации

Цитаты переезжают в Astro content collection `quoteAuthors`. Один автор — один YAML-файл `src/content/quotes/<author>.yaml` с метаданными и массивом `quotes`, структура проверяется Zod-схемой, имена для отдельных цитат не нужны. Тематические страницы становятся `.mdx` и выводят цитаты компонентом `<QuoteList topic="…" />`. URL и внешний вид сохраняются. Заодно исправляются битые ссылки на цитаты в `index.md`, `README.md` и `quotes/index.md`, а процесс ingest переходит на новый формат.

## Опциональные разделы

### Открытые вопросы

- **Стабильность id цитат.** id `<author>/<n>` зависит от позиции в массиве. Правило «только дописывать в конец» защищает id при добавлении, но не при удалении или перестановке. Пока на цитаты никто не ссылается по id, этого достаточно. Если бот начнёт хранить id (например, «цитата дня» или история показов), нужно добавить необязательное поле `id` или брать хеш текста.
- **Бот и KB.** По [260515-bot.md](./260515-bot.md) бот собирает в system prompt Markdown-файлы из `src/content/docs/`. После миграции в `.mdx` останется только `<QuoteList />` без текста цитат. Нужно решить, как бот получит цитаты: сборщик KB дополнительно читает `src/content/quotes/*.yaml`, или цитаты экспортируются при сборке (например, в `quotes.json` в `public/`). Сборщика в репозитории пока нет, поэтому этот RFC вопрос не закрывает. Решить его нужно до подключения KB к боту.
- **Контекст цитаты по теме.** Одна цитата на разных страницах сейчас идёт с разными «Контекст» и «Для размышления». В этом RFC оставляем один вариант. Если окажется, что разница важна, можно перейти на `notes: { <topic>: { context, reflection } }`.
- **Страницы авторов** (`/quotes/authors/leo-tolstoy/`) через `src/pages/...` + `StarlightPage`. Данные это позволяют (`getQuotes({ author })`), но в объём RFC страницы не входят.
- **Автор цитаты «Грамм собственного опыта…»** в `wisdom-knowledge.md` не указан, заголовок секции — «Грамм собственной жизни». Нужно подтвердить автора и перенести запись из `folk-wisdom.yaml`.
- **Размещение данных.** Выбрано `src/content/quotes/`, а не `src/content/docs/quotes/`. `docsLoader` YAML не читает, но данные и страницы в одном дереве путают агентов и `autogenerate` сайдбара. Если нужно именно внутри `docs/quotes/`, меняется только `base`.

### Альтернативные варианты

**Вариант A: один YAML на автора с массивом цитат (выбран).**
Плюсы: не нужно придумывать имена для цитат, всё про автора в одном месте, ~20 файлов вместо ~110, дублей автора по построению нет.
Минусы: id цитаты зависит от позиции; у плодовитых авторов (Толстой, 18+ цитат) файлы длиннее; выше шанс конфликта при параллельных правках одного автора.

**Вариант B: один YAML на цитату в папке автора.**
Плюсы: минимальные диффы, стабильный id из имени файла.
Минусы: для каждой из ~110 цитат нужен slug, метаданные автора приходится выносить в служебный `_author.yaml`, нужна отдельная проверка «папка без автора». Отклонён: придумывать имена файлов слишком дорого.

**Вариант C: оставить Markdown и навести порядок.**
Плюсы: ноль инфраструктуры.
Минусы: не решает дублирование, валидацию и выборку по автору и теме — ни одну из целей.
